## 改完必做（每次改动后的固定动作）

**动过前端或数据后，按顺序走完这几步，否则仓库、程序目录、单文件包三者会脱节。**

### 1. 重建数据（动过 `源数据`、抽取逻辑或语料时）

```bat
python 工具\extract.py --out 数据\_pages.jsonl
python 工具\build_final.py
python 工具\build_toc.py
python 工具\build_nummap.py
python 工具\build_menus.py
```

然后把 `数据\package\*.json.gz` 同步到 `前端\proto\data\`，**只复制内容有变化的文件**。
（顺序不能反：`build_toc` 依赖新的 `pages.json`，第 44 节的 MA136 就是重跑顺序错了才复活不了。）

### 2. 体检（动过抽取逻辑时）

```bat
python 工具\audit_data.py
```

「无法配对」「语料键缺失」两项必须为 0；其余条目人工扫一眼。
它只看不写，输出的 `验证\数据异常日志.md` 可直接提交。

### 3. 同步到程序目录

```bat
cd 构建\Windows
打包.cmd
```

会把 `前端\proto` 镜像进 `dist\莊春江讀經站\ui`，并把 `src\授權說明.txt` 写进两个成品目录。
改完界面不跑这步，exe 里看到的还是旧页面。

### 4. 重编单文件包（需要更新 exe 时）

```bat
python 工具\build_zip.py
```

再按**第 48 节**的 `csc` 命令编译（漏 `System.IO.Compression` / `System.IO.Compression.FileSystem`
会报 `CS0246: ZipArchive`），最后重打 `庄春江工作站软件版.zip`（exe + 三个说明文件）。

### 提交前

- `git status` 只应出现预期文件；`dist\`、`构建\Windows\build|pkg`、`.tools\` 都在 `.gitignore` 里；
- **重建噪音**：`books.json.gz` 这类「内容没变、只是序列化顺序不同」的文件要还原成原文件，
  别让无意义的二进制 diff 混进提交（第 45、46 节都踩过）。
- 改完功能顺手补一条本节之外的日志，写清「为什么改」而不只是「改了什么」。

### 4. 抽取器迭代（遇到的问题）

1. **lxml 整页解析会丢内容**：`SA0541` 等页面因 `<p>`/`<font>` 未闭合、`<div>` 套在 `<p>` 里，
   libxml2 按 HTML4 规则把正文整段丢弃。→ 改为「原始字符串 + `<div>` 深度配对」定位内容块，
   绕开浏览器式解析规则。
2. **BOM/杂字符**：部分文件以 `\ufeff` + 杂字母开头，导致没有 `<body>`。→ 解析前清洗。
3. **重复内容**：新版页面同页存了繁、简两份；栏目目录页整页也是繁简双份。
   → 只取 `.trad` 块；清洗时丢弃 `class` 含 `simp` 的元素。
4. **页头/导航混入**：栏目页、著作页带搜索栏/菜单。→ 按 id（`lang-bar`、`notediv`）剥离；
   著作优先取 `#maindiv`。
5. **行内字号陷阱**：部分页面用 `<span style="font-size:20pt">` 包住整篇正文，
   若当作标题放大，整页字会变大。→ 只有文本 ≤ 40 字的元素才保留字号/颜色，
   映射为 `data-fs` / `data-c`。
6. **注释链接**：`onMouseover="note(this,N)"`、`local(this,N)`、`note_over(N)` 三种写法，
   统一转成 `class="n|l" data-n="N"`，不再依赖内联事件。

### 7. 存储形式对比（回答「数据库是不是更小」）

用同一批 7615 页正文做的实测：

| 形式 | 体积 |
|---|---|
| HTML（含标记） | 64.10 MB |
| 纯文本（去标签） | 58.23 MB |
| **SQLite（纯文本，无索引）** | **62.95 MB** |
| SQLite（每页 gzip 存 BLOB） | 21.04 MB |
| **当前方案：按栏目 JSON + gzip** | **14.38 MB** |

结论：**数据库不会更小**。SQLite 不压缩文本，存储是当前方案的 4 倍多；
即使每页单独 gzip，也因丢失跨页冗余而比现在大 46%。
数据库的优势在随机读取和查询，不在体积。当前页数（7600）和单栏目体积（最大 2 MB gzip）都很小，
整栏目一次载入内存完全可行，暂时不需要数据库。

### 10. 重复度分析（用户提出「按栏目建语料库」后的测量）

用户设想：以栏目为独立仓库，页面只存「引用」，不重复存另一侧的文本和巴利原文。

实测结果（7615 页，总文本 3036 万字）：

| 块类型 | 字数 | gzip | 占压缩体积 |
|---|---|---|---|
| 巴利原文 | 2103 万 | 4.31 MB | 33.2% |
| 南传汉译（nikaya） | 750 万 | 4.41 MB | 33.9% |
| 北传汉译（agama） | 243 万 | 1.88 MB | 14.4% |
| 著作/说明（doc） | 149 万 | 1.45 MB | 11.1% |
| 比对（cmp） | 84 万 | 0.56 MB | 4.3% |
| 旧版正文 | 51 万 | 0.39 MB | 3.0% |

「北传页（SA/MA/DA/AA）里嵌入的南传文本 + 巴利原文」：

- 1396 页有嵌入
- 南传中文 232.6 万字 + 巴利 596.2 万字 = **828.9 万字，占全部文本 27.3%**

另：SQLite 对比（同批数据）：纯文本 62.95 MB、每页 gzip BLOB 21.04 MB、当前 JSON+gzip 14.38 MB。
数据库不会更小。

### 38. 单文件版（内存运行，不解压）

按用户要求做了「不解压」的单文件 exe：

- 单实例、WebView2 缺失提示、DPI 清单、复制粘贴均保留；
- 成品：`dist\單文件版\莊春江讀經站.exe`，**13.91 MB**，附使用说明。

注意：`userdata`（缓存/阅读记录）仍在 exe 旁生成，无法塞进 exe。

首次实测单文件版时报错：`%TEMP%\ZCJReader\loader\x64` 访问被拒绝。
已改为三级回退：`%LOCALAPPDATA%\ZCJReader\loader` → `%TEMP%\ZCJReader\loader` →
程序目录 `loader`；全部失败时弹窗列出尝试过的路径与最后错误，不再抛未处理异常。

**又一处调整**：单文件版仍会在程序目录生成 `userdata`（WebView2 缓存，约 10 MB），
不符合「只有一个 exe」的预期。改为：

- 默认数据目录 `%LOCALAPPDATA%\ZCJReader\WebView2`，程序目录不产生任何文件；
- 缓存上限 50 MB（`--disk-cache-size=52428800`）；
- 需要便携（U 盘）时，在 exe 旁放一个空 `portable.txt`，数据改放 exe 旁 `userdata`。

**最终结论（重要）**：单文件版在 DSH 里启动时报「四个路径全部拒绝访问」，
但用 PowerShell 建同样的目录却成功。原因是**启动方式**：从 DSH 界面启动的进程
继承了本会话的沙箱策略，只能写工作区；从桌面/资源管理器启动则完全正常，
`%LOCALAPPDATA%` 写入成功、程序目录不生成任何文件夹。
程序本身没有问题。为兼顾受限环境，回退顺序最终为：
`%LOCALAPPDATA%` → `%APPDATA%` → `%ProgramData%` → `%TEMP%` → exe 旁的 `userdata`。

### 54. 图标去掉白底（透明化）
